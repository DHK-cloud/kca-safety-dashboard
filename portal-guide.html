이후에는 화면에서 관리합니다.

운영부서: KCA 부산본부. 맞춤 제작한 GitHub Pages 포털에 Google Apps Script·Sheets·Drive를 연결합니다. Google Sites를 사용하지 않습니다.

현재 상태

화면과 연결 코드는 준비했고, 비공개 기록 시트와 콘텐츠 관리 시트를 새로 만들었습니다. Google 로그인 설정과 Apps Script 초기 실행·배포를 완료했습니다. GitHub에는 기존 홈페이지와 별도의 검토 화면을 게시했습니다. 실제 로그인·보고 저장·관리자 편집은 배포 화면에서 검증 중입니다. 교육파일은 아직 등록 전입니다.

사용자는 이렇게 이용합니다.

  1. 안전점검 또는 작업중지권 보고를 누릅니다.
  2. 위치 사용을 허용했다면 주소를 자동으로 채웁니다. 주소와 현장 유형을 확인하고 결과를 선택합니다.
  3. 저장을 누릅니다. 최초 Google 로그인 이후 같은 방문에서는 다시 로그인하지 않습니다.

이름·소속만 기기에 기억합니다. 실제 기록은 Google Sheets에 저장하므로 브라우저 데이터를 지워도 클라우드 기록은 유지됩니다. ‘이상 없음’은 사용자의 간편 확인 선언이며 개별 12개 항목에 자동으로 ‘적합’을 기록하지 않습니다.

관리자는 이렇게 이용합니다.

  1. 관리자 편집에서 Google 계정으로 로그인합니다.
  2. 콘텐츠·카테고리·캠페인·포털 안내를 수정합니다. 파일은 Drive에 업로드하고 링크만 등록합니다.
  3. 등록·수정 사유를 입력하고 저장합니다. 이전 버전은 수정 이력에서 복원할 수 있습니다.
  4. 보고 기록을 확인하고 CSV 또는 전체 JSON 백업으로 보관합니다.

파일을 교체할 때에는 이전 파일을 바로 삭제하지 말고 Drive의 보관 폴더에 유지하세요. 수정 이력은 링크와 설명을 보관하며 삭제된 파일 자체를 복구하지는 못합니다.

영상은 Drive에서 재생합니다.

기존 구독 Google 계정의 Drive에 영상을 보관합니다. YouTube는 사용하지 않으므로 YouTube 검색·추천으로 노출되지 않습니다. 직원 계정을 뷰어로 지정하고 일반 액세스는 ‘제한됨’으로 둡니다. 포털 허용 계정 등록과 Drive 공유는 별도입니다.

삽입 재생이 실패하면 ‘Drive에서 직접 열기’를 이용합니다. 업로드 직후에는 영상 처리에 시간이 걸릴 수 있습니다. Drive 영상 재생 안내 · 공유 권한 안내

기존 Google 시트는 유지합니다.

  • 기상 현황판 ID와 ‘재난안전 현황판’ 탭 A11:K30을 그대로 읽습니다. 현재 범위는 부산본부 관할이며 전국 기상으로 표시하지 않습니다.
  • 기존 보고 응답 시트 ID를 지정하면 KCA_전국안전기록 탭만 추가합니다. 기존 응답 행·기존 폼·기상 자료를 변경하지 않습니다.
  • 교육 관리 데이터는 별도 콘텐츠 시트에 저장합니다. 기존 점검 기록과 교육 자료 목록을 섞지 않습니다.
설치 담당자용 · 최초 연결 절차 펼치기

1. Google 저장소 준비

이번 개편에는 새 기록 시트와 콘텐츠 관리 시트를 이미 준비했습니다. 별도로 전달한 ‘운영연결정보.html’의 두 ID를 사용하세요. 해당 파일은 공개 사이트에 올리지 않습니다. 기상 시트 ID를 기록용으로 지정하지 마세요.

기록 시트와 콘텐츠 시트는 ‘웹에 게시’하지 않습니다. 직원 계정에 시트 전체 편집 권한을 줄 필요가 없습니다. Apps Script가 소유자 권한으로 저장하고, 서버에서 요청자의 Google 서명과 역할을 확인합니다.

2. Google 로그인 설정

Google Cloud Console에서 결제 계정을 연결하지 않은 프로젝트를 만들고 Google Auth Platform에 앱 이름과 담당 이메일을 등록합니다. 웹 애플리케이션 OAuth 클라이언트를 생성합니다. 별도 유료 API나 저장소는 활성화하지 않습니다. 로그인에만 openid / email / profile를 사용합니다.

승인된 JavaScript 원본은 https://dhk-cloud.github.io입니다. 로컬 검증이 필요하면 http://127.0.0.1:8765도 등록합니다. Google 계정 종류와 조직 정책에 따라 테스트 사용자 등록이나 배포 설정이 필요할 수 있습니다. Google 공식 설정 안내

3. Apps Script 코드 등록

Google Apps Script에서 새 프로젝트를 만듭니다. apps-script/Code.gs와 apps-script/JwtLibrary.gs를 각각 스크립트 파일에 복사합니다. 설정에서 매니페스트 표시를 켜고 appsscript.json도 복사합니다. 라이브러리는 jsrsasign 11.1.5 npm 배포본이며 MIT 라이선스를 포함했습니다.

스크립트 속성에 다음 값을 등록합니다. 비밀번호나 OAuth 클라이언트 비밀은 필요하지 않습니다.

키값
GOOGLE_CLIENT_ID웹 OAuth 클라이언트 ID
PORTAL_ORIGINhttps://dhk-cloud.github.io
ADMIN_EMAILS관리자 Google 이메일. 여러 계정은 쉼표로 구분
REPORT_SPREADSHEET_ID준비된 새 기록 시트 ID
CONTENT_SPREADSHEET_ID준비된 새 콘텐츠 관리 시트 ID

편집기에서 setup을 한 번 실행하고 Google의 권한 요청을 확인합니다. Sheets 접근과 인증용 공개키 조회 권한을 사용합니다. 기존 소유자가 지정한 시트만 연결하세요. 결과의 시트 URL을 보관합니다.

4. 웹앱 배포

배포 → 새 배포 → 웹앱에서 ‘실행 사용자: 나’, ‘액세스: 모든 사용자’로 설정합니다. 이 접근 설정은 공개 피드와 로그인 화면을 제공하기 위한 것입니다. 직원 자료·관리자 편집·기록 조회는 모든 요청에서 Google 서명과 허용 계정을 확인합니다. 익명 사용자에게는 공개 교육자료만 반환합니다.

/exec로 끝나는 배포 URL을 복사합니다. 본격적인 운영 전 아래 권한 검증을 반드시 실행합니다. 조직 정책상 익명 배포를 허용하지 않으면 해당 정책에 맞게 연결 방식을 조정해야 합니다.

5. 포털 최초 설정

config.js의 세 값만 설정합니다. 운영 중 콘텐츠 편집에는 코드를 수정하지 않습니다.

feedUrl: "https://script.google.com/macros/s/배포ID/exec",
apiUrl: "https://script.google.com/macros/s/배포ID/exec",
googleClientId: "클라이언트ID.apps.googleusercontent.com"

6. GitHub Pages에 배포

기존 저장소를 먼저 백업하거나 별도 브랜치에서 검토합니다. 공개 포털 파일들을 배포 루트에 놓고 GitHub Pages로 배포합니다. apps-script/, 관리 시트 백업, 직원 자료 원본은 사이트 자산으로 올릴 필요가 없습니다. 기존 홈페이지는 실제 배포 전까지 변경되지 않습니다. 매뉴얼 원본 PDF도 공개 패키지에 포함하지 않았습니다.

7. 운영 계정과 파일 연결

관리자 편집 → 허용 계정에서 직원 Google 이메일을 등록합니다. 권한을 철회하면 다음 요청부터 접근을 차단합니다. Drive 폴더에서도 같은 계정의 공유 권한을 설정합니다. 직원 콘텐츠는 ‘직원용’으로 등록하고 영상은 Drive 파일의 /file/d/파일ID/view 링크를 연결합니다.

8. 실제 계정으로 최종 확인

  • 허용 직원: 기록 저장 → 기록번호 확인 → 기존 시트의 새 KCA 탭에서 동일 내용 확인
  • 관리자: 내용 정정·카테고리 추가·수정 이력 복원·백업 확인
  • 외부 계정: 직원 자료·기록·관리자 기능 접근 거절 확인
  • Drive 권한 없는 계정: 직접 영상 URL로도 열람 불가 확인
  • 브라우저 데이터 삭제 후: 클라우드 기록과 교육 자료 목록 유지 확인
  • 모바일 GPS: 실제 위치 허용·거부·타임아웃, 주소 추정과 수동 수정 확인
  • Apps Script의 POST 응답이 포털에 전달되는지 확인. 미확인 시 완료 표시 없이 재시도

실제 Google 배포 환경에서는 인증·공유 정책과 iframe 응답 동작을 반드시 검증해야 합니다. 현재 로컬 검증이 클라우드 저장 검증을 대신하지 않습니다.

운영 범위와 참고

추가 유료 서비스·도메인은 사용하지 않습니다. 이미 구독 중인 Drive 공간을 활용합니다. Apps Script 무료 사용량과 Drive 재생·공유 제한은 적용되며, 구독 용량이 무제한인 것은 아닙니다. Apps Script 제한

GPS 주소 추정은 기존 사이트와 같은 OpenStreetMap Nominatim을 사용합니다. 위치 버튼을 누르거나 이미 위치 사용을 허용한 경우에만 좌표를 주소 조회 서비스에 전송합니다. 정밀 좌표는 보고 기록에 보관하지 않습니다. 주소와 시·도는 수정할 수 있습니다. Nominatim 사용 정책

요약과 점검 항목의 기준은 사용자가 제공한 ‘무선국 검사 안전매뉴얼’, KCA-KSJ-01 Rev.4, 2026.07.07입니다. Ⅲ. 1 작업중지권(26~27쪽), 2.1~2.8 현장 기준(28~33쪽), 2.9 점검표(34쪽), 2.10 보고서식(35쪽), 검사단계별 프로세스(7쪽)를 참조했습니다. 원문은 등록 전 관리자 검토를 거쳐 Drive에 연결하세요.
